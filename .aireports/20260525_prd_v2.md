## 1. 摘要

**sextant** 是一个多项目 Agent 协同工具。在**一个终端 REPL** 中管理多个 Claude Code Agent，用户在项目间切换、投递消息、审批操作——用户始终是编排者，Agent 是执行者。

**核心机制**：
- Agent 通过 `send_message` 向其他项目**投递**消息（写入 mailbox，立即返回）
- 用户通过 `/chat <project>` 切换到目标项目，**看到待处理消息，按回车发送**
- Agent 的每次操作通过 `canUseTool` 弹窗等待用户审批
- **Agent 输出不回写**——需要回复时由用户显式指示 Agent 调 `send_message`

**一句话定位**：一个 REPL，多个 Agent，用户编排，消息显式投递。

## 2. 核心设计原则

| # | 原则 | 含义 |
|---|------|------|
| P1 | **project_id = basename(cwd)** | 项目标识等同于工作目录名 |
| P2 | **全局串行** | 同一时刻只有一个 Agent 在处理 prompt |
| P3 | **用户是编排者** | 消息投递、Agent 间回复均由用户显式触发，无隐式行为 |
| P4 | **send_message 投递即忘** | Agent 写入 mailbox 即返回；收件人看到时由用户决定是否发送 |
| P5 | **mailbox 是消息暂存区** | Agent 发出的消息存入收件人 mailbox；用户切换项目时展示为 draft |
| P6 | **Agent 输出不回写** | Agent 的文本输出仅展示给用户；需回复时用户指示 Agent 主动调用 `send_message` |

```
│  │  ncp: ClaudeSDKClient    ← 后台等待              │    │
│  │  xcp: ClaudeSDKClient    ← 后台等待              │    │
│  │                                                │    │
│  │  canUseTool 回调 → 拦截工具审批 / AskUserQuestion│    │
│  └──────────────┬──────────────────────────────────┘    │

│  │                                                │    │
│  │  send_message() → 写入收件人 mailbox             │    │
│  │  /chat <proj>  → 读取该 proj 的待处理消息        │    │
│  └────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### 3.2 模块职责

| 模块 | 职责 |
|------|------|
| `cli.py` | REPL 入口：输入循环、`/chat` 命令、`/help` 等 |
| `session.py` | ClaudeSDKClient 生命周期 + `canUseTool` 回调 |
| `send_message.py` | 唯一 MCP tool：写 mailbox → 返回 ack |
| `mailbox.py` | 消息持久化：写入、按收件人查询、状态管理 |
| `config.py` | `sextant.yaml` 解析 |

### 3.3 与 v1.x 的关键差异

| v1.x | v2.0 |
|------|------|
| `route_message` 同步阻塞注入 | 不存在（send_message 只写 mailbox） |
| `_call_stack` 递归防护 | 不存在（异步解耦） |
| Agent 输出自动回写 mailbox | Agent 输出仅展示，不回写 |
| `send_message(to="__user__")` | 不存在（用户交互走 canUseTool） |
| System prompt 教 Agent "请用 send_message 回复" | 不存在（Agent 不需要知道回复机制） |
| Ctrl+C → `sextant chat ncp` 切项目 | `/chat ncp` 在 REPL 内切换 |

## 4. 消息模型

### 4.1 消息生命周期

```
Step 1: 用户对 acp 说"通知 ncp 改 XXX"
        → acp 调用 send_message(to="ncp", subject="...", body="...")
        → mailbox.record(to="ncp", ...)
        → 返回 {"status": "sent"} 给 acp
        → acp 继续工作

Step 2: 用户输入 /chat ncp
        → 当前活跃项目切换为 ncp
        → mailbox.get_pending(to="ncp") → 取出待处理消息
        → REPL 显示 draft:

          [来自 acp] 同步协议变更：Token → TokenStruct
          Token 字段从 string 改为 TokenStruct...

          --- 按回车发送，或输入新内容覆盖 ---

Step 3: 用户按回车（或编辑后按回车）
        → 内容作为 prompt 发送给 ncp agent
        → ncp 处理，canUseTool 弹窗审批
        → 输出展示给用户

Step 4: （可选）用户对 ncp 说"告诉 acp 改完了"
        → ncp 调用 send_message(to="acp", subject="Re: ...", body="改完了")
        → 写入 acp 的 mailbox
```

### 4.2 send_message 语义

```
Agent 调用: send_message(to="ncp", subject="...", body="...")
sextant 动作: mailbox.record(to="ncp", from="acp", ...)
返回值: {"status": "sent", "msg_id": "m_xxx"}

Agent 应理解为 "消息已投递，对方下次查看时会看到"
Agent 不应等待回复（返回即完成）
```

### 4.3 /chat 命令语义

```
/chat ncp
  → 切换当前活跃项目为 ncp
  → 查询 mailbox 中 to="ncp" 的待处理消息
  → 拼装为 draft 文本展示在 REPL 中
  → 用户按回车发送给 ncp agent
  → 用户也可编辑/追加内容后发送

/chat acp
  → 同上，切换到 acp
```

### 4.4 Mailbox 数据结构

```python
{
  "msg_id": "m_20260525_001",
  "timestamp": "2026-05-25T15:30:00+08:00",
  "from": "acp",
  "to": "ncp",
  "subject": "同步协议变更：Token → TokenStruct",
  "body": "Token 字段从 string 改为 TokenStruct...",
  "status": "pending"       # pending | delivered
}
```

- `status=pending`: 消息已写入，收件人尚未查看
- `status=delivered`: 消息已通过 `/chat` 展示给用户并发送

### 6.3 场景关键洞察

#### 为什么 Agent 输出不回写？

因为回写是**猜测用户意图**。用户可能想让 acp 知道，也可能不想。可能想加一句点评再发，也可能想合并多条结果后一起发。由用户显式指示 Agent 调 `send_message`——零歧义。

#### 为什么 /chat 展示 draft 而不是直接注入？

因为用户可能需要**审阅**消息内容。acp 发的消息可能不完整、不清楚，用户在发送前可以修改或追加说明。用户也可能不想处理某条消息——直接清空输入框或切走即可。

#### 用户在什么时候指示 Agent 回复？

在处理完消息、看到 Agent 输出之后。用户评估输出质量，决定是否需要通知其他项目。这是编排者的自然行为——不需要系统猜测。

## 7. API 规范

### 7.1 `send_message` MCP Tool

**描述**: 向其他项目发送消息。写入目标项目 mailbox 后立即返回。

**参数**:

| 参数 | 类型 | 必填 | 描述 |
|------|------|------|------|
| `to` | string | 是 | 收件人 project_id |
| `subject` | string | 是 | 消息主题 |
| `body` | string | 是 | 消息正文 |

**返回值**:

```json
{
  "status": "sent",
  "msg_id": "m_20260525_001",
  "to": "ncp"
}
```

**行为契约**:
1. 写入收件人 mailbox（JSONL），`status=pending`
2. 立即返回，不阻塞
3. 目标 project_id 不存在时返回 `{"status": "error", "message": "项目不存在"}`
4. 消息在收件人通过 `/chat` 切到该项目时展示为 draft

### 7.2 `/chat <project>` 命令

**描述**: 切换当前活跃项目，并展示目标项目的待处理消息。

**行为**:
1. 将当前活跃项目切换为 `<project>`
2. 查询 mailbox：`status=pending AND to=<project>` 的所有消息
3. 按时间顺序拼装为 draft 文本
4. 在 REPL 中展示 draft，用户按回车发送给 Agent
5. 已展示的消息标记为 `status=delivered`

**draft 格式**:
```
切换到 <project>。你有 N 条待处理消息：

[来自 <sender>] <subject>

<body>

──────────────────────────────────────────
> █
```

## 8. 会话管理

### 8.1 会话创建

```python
for project in config.projects:
    client = ClaudeSDKClient(options=ClaudeAgentOptions(
        cwd=project.directory,
        permission_mode="default",       # canUseTool 控制审批
        setting_sources=["project"],
        continue_conversation=True,
        env=_load_claude_env(),
        mcp_servers={"sextant": mcp_server},
        can_use_tool=can_use_tool,       # 统一审批回调
        hooks={"PreToolUse": [HookMatcher(matcher=None, hooks=[dummy_hook])]},
        system_prompt={
            "type": "preset",
            "preset": "claude_code",
            "append": _build_system_prompt(project.id, config.projects),
        },
    ))
    await client.__aenter__()
```

### 8.2 System Prompt

```
你的项目是 {project_id}。

可以通过 send_message(to, subject, body) 向以下项目发消息：{other_projects}。
消息发送后对方下次查看时会看到。

用户交互相通过弹窗进行——需要审批的工具或需要确认的问题会自动弹出。
```

**注意**: 
- 不再教 Agent "请用 send_message 回复"
- 不再提及 `__user__`
- 不提 mailbox 或消息投递机制——Agent 只需知道 `send_message` 会送达

### 8.3 canUseTool 回调

```python
async def can_use_tool(tool_name, input_data, context):
    # MCP 内部工具永远放行
    if tool_name == "send_message":
        return PermissionResultAllow(updated_input=input_data)

    # Agent 提问
    if tool_name == "AskUserQuestion":
        return await _handle_ask_user_question(input_data)

    # 其他工具 → 弹窗审批
    desc = _format_tool_for_user(tool_name, input_data)
    reply = await _prompt_user(f"允许 {tool_name}?", desc)
    if reply in ("y", "yes", "是"):
        return PermissionResultAllow(updated_input=input_data)
    return PermissionResultDeny(message="用户拒绝")
```

## 10. 开放问题与风险

| # | 问题 | 风险 | 缓解 |
|---|------|------|------|
| Q1 | `/chat` 切换时如果当前 Agent 正在处理中？ | 中 | 不允许在 agent 响应中切换；等当前 turn 完成 |
| Q2 | 多条 mailbox 消息的 draft 长度可能超过 token 限制？ | 低 | mailbox 消息一般较短（指令型），多条时限制展示条数或截断 |
| Q3 | 用户忘记 `/chat` 查看消息，mailbox 堆积？ | 低 | 状态栏显示待处理数；`sextant status` 展示各项目消息数 |
| Q4 | 如果用户想同时看到 ncp 和 xcp 的进度？ | 低 | v2.0 串行模型不支持；Phase 10+ 可考虑分屏或多面板 |
| Q5 | Agent 会不会自己决定调 `send_message` 而不是等用户指示？ | 中 | System prompt 中说明"仅在用户明确要求时使用 send_message"；Agent 倾向遵循指令 |
